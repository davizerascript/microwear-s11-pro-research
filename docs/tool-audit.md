Este documento registra o estado após a revisão de segurança e os testes em 2026-10-22. As ferramentas foram executadas somente contra arquivos fornecidos ou derivados locais. Nenhuma ferramenta escreveu no relógio ou no UFW original.

## Corrigido nesta revisão

1. O cálculo do cabeçalho flash usa os bytes totalmente decifrados antes de restaurar VID/PID para apresentação. O CRC correto é `0xF520`; `0x400C` era de uma representação diferente.
2. O `data_crc` JLFS de `uboot.boot` é comparado após `descramble_bankcb`, não contra o payload bankcb-scrambled. O corpo e o cabeçalho bankcb também foram validados separadamente.
3. A especificação pública documenta LZ4 para `uboot.boot` com flag `0x40`. A documentação e o auditor agora registram esse fato, mas distinguem-no de uma descompressão — que não foi executada.
4. O patcher JCRT usava um fim hardcoded que deixava de fora o sétimo descritor; agora calcula a extensão com `item_count` e valida o CRC original antes do dry-run/patch.
5. O JSON dos parâmetros `isd_config.ini` agora aponta para o arquivo interno JLFS de 127 bytes, não para a entrada UFW externa de 1.273 bytes com mesmo nome.
6. A documentação do Ghidra agora separa métricas do listing de contagens reais, descreve erros/conflictos de decodificação e identifica `0x0` como base imposta, não comprovada.

## Recomendação antes de publicar

O workspace ainda não é uma release reproduzível em clone limpo. Não inclua `original/`, `work/`, dumps, imagens extraídas, projeto/binário Ghidra, toolchain baixada ou cópias de SDK/repositórios de terceiros sem confirmar direito de redistribuição. O `.gitignore` do repositório exclui esses itens localmente. Antes de declarar as ferramentas independentes, empacote/dependencie formalmente parser/cifra/CRC, converta `extract_jlfs.py` para CLI com entrada/saída explícitas e adicione limites de recursos ao carving BCSDIAL. Consulte também `PROGRESSO.md` para bloqueios de hardware e recuperação.
